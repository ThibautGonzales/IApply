# IApply backend

FastAPI application.

## Run locally (without Docker)

```bash
cd backend
python -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
# Point to a running PostgreSQL (for example the one from docker compose)
export DATABASE_URL=postgresql+psycopg://iapply:iapply@localhost:5432/iapply
fastapi dev app/main.py        # http://localhost:8000/health and /docs
```

## Run the tests

Tests use an in-memory SQLite database (see `tests/conftest.py`), so they
don't need PostgreSQL.

```bash
cd backend
python -m pytest
```

Without Python installed, run them inside the backend image (from the repository root).
Postgres is not started and your database is never touched; the tests folder is mounted
because the image leaves it out. In Git Bash, `MSYS_NO_PATHCONV=1` stops it from turning
`/app/tests` into a Windows path.

```bash
MSYS_NO_PATHCONV=1 docker compose run --rm --build --no-deps -e DATABASE_URL=sqlite:// -v ./backend/tests:/app/tests backend python -m pytest
```

## Database migrations

The schema is managed by Alembic (`alembic.ini`, `migrations/`). In Docker, the
backend applies pending migrations at startup (`alembic upgrade head`).

```bash
cd backend
alembic upgrade head                              # apply pending migrations
alembic revision --autogenerate -m "add x table"  # create a migration after changing a model
```

Always read an autogenerated migration before committing it: Alembic guesses
the changes and can miss some (renamed columns, for example).
